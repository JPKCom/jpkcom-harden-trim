features-performance.php

Performance features

Emoji, self pingbacks, asset versions, post embeds, comment-reply, dashicons, block library CSS, global styles, heartbeat, revisions and the autosave interval.

Hooks are only added for features whose value is active. Role-scoped features decide inside their callbacks, where the current user is known; global features act for everyone. Every hook name and priority below was checked against the WordPress 7.1.3 source.

Paths of the other sites of a multisite installation on a host.

jpkcom_harden_trim_sibling_site_paths(string $host) : array<int, string>

On the main site of a subdirectory network home_url() has no path, so host and path prefix alone would count every sibling site as "self". Every site with the same domain (with or without www.) except the current one is listed, in any network and any status: a path that belongs to another site is never the current site's. Cached per request, current site and host; empty on a single site.

jpkcom_harden_trim_is_self_link()

features-performance.php : 341

Whether a URL points to this site (home or WordPress address).

jpkcom_harden_trim_is_self_link(string $url) : bool

Host and path prefix: the host is compared without scheme, www. and letter case, and the link's path must start with the path of home_url() or site_url() at a segment boundary. On a subdirectory multisite (or a second WordPress under a path) a link to a sibling site on the same host is therefore not a self ping. On the main site of such a network (home without a path) a link into the path of another site of the network is not a self ping either (see jpkcom_harden_trim_sibling_site_paths()); a single site is unaffected.

Parameters
$url : string

URL to check.

Tags
since
1.0.0
Return values
bool —

True for a link to this site.

jpkcom_harden_trim_heartbeat_disabled_handles()

features-performance.php : 777

Script handles that print nothing while heartbeat is disabled.

jpkcom_harden_trim_heartbeat_disabled_handles() : array<int, string>

Mechanism (read from 7.1.3 script-loader.php, class-wp-dependencies.php, class-wp-scripts.php, edit-form-blocks.php and js/dist/editor.js):

  • Deregistering heartbeat is not an option: autosave and wp-auth-check depend on it, and WP_Dependencies::all_deps() then raises _doing_it_wrong for the missing dependency (since 6.9.1).
  • Instead the handles stay registered and resolvable, and script_loader_src returns '' for them. WP_Scripts::do_item() then returns before building the tag, so neither the file nor its inline before/after scripts are printed. That drops edit-form-blocks.php's inline wp.heartbeat.interval( 10 ), which would throw without heartbeat.js. Only the localized heartbeatSettings variable remains.
  • autosave goes too: its triggerSave() calls wp.heartbeat.connectNow() unguarded (Ctrl+S, slug blur in the classic editor). Every caller of wp.autosave in core checks wp.autosave first, and every core caller of wp.heartbeat outside autosave.js checks wp.heartbeat first.
  • The block editor (js/dist/editor.js) only uses heartbeat.send / heartbeat.tick hook actions and its own REST autosave, so it runs without heartbeat; wp-auth-check is also switched off via wp_auth_check_load, which removes its CSS and markup as well.
Tags
since
1.0.0
Return values
array<int, string> —

Script handles.
