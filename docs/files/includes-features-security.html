features-security.php

Security features

Neutral login error, response headers, fingerprint headers, JSONP, file editor and application passwords. All of them are global: they act on anonymous requests, headers or constants, where no user context exists, so the exempt roles do not apply. Hook names were checked against the WordPress 7.1.3 source.

jpkcom_harden_trim_filter_login_errors()

features-security.php : 130

`wp_login_errors` callback, limited to the login form.

jpkcom_harden_trim_filter_login_errors(mixed $errors[, mixed $redirect_to = '' ]) : mixed

wp-login.php applies the filter in two places: the checkemail case and the login case (case 'login': default:, so every unknown action is a login request too). The lost-password flow does not use it, and checkemail never carries credential errors, so only that action is skipped; gating on login alone would let action=foo bypass the neutral message.

jpkcom_harden_trim_security_headers()

features-security.php : 167

Security response headers to send for the active settings.

jpkcom_harden_trim_security_headers(array<string, mixed> $settings, array<int, string> $already_sent, bool $is_ssl, bool $is_embed) : array<string, string>

A header whose name is already in $already_sent (set in PHP by core or another plugin) is never returned, so the plugin cannot override it. headers_list() only knows headers set in PHP: one added by the web server (nginx add_header, Apache mod_headers) or a CDN is invisible here and would be sent twice.

Effective settings.
