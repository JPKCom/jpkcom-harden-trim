jpkcom_harden_trim_core_control_value()

admin-page.php : 581

What a field locked by a core constant shows: the core value, read the way core reads it.

jpkcom_harden_trim_core_control_value(string $key, mixed $value) : array{value: mixed, other: string|null}

The control of a core-locked field must show what is in effect, which is the core constant (core honours it and the feature code then does nothing), never the stored value or an ignored plugin constant. Core reads (7.1.3):

  • DISALLOW_FILE_EDIT: truthy disables the editors (capabilities.php:609).
  • WP_AI_SUPPORT: falsy disables AI (ai-client.php:23); the field is "Disable core AI features", so it is checked for a falsy value.
  • WP_POST_REVISIONS: true is unlimited, anything else is cast to int (revision.php:813-818); a negative number is unlimited as well, which is what "WordPress default" means for this field. 0 and the listed limits select their option.
  • AUTOSAVE_INTERVAL: seconds handed to the editor (script-loader.php:1962); 60 is core's own default (default-constants.php:381). A value no option names is returned as other, the text of an extra option the disabled select shows selected.
