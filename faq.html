How do I set options in wp-config.php?

Define the constant before the “That’s all, stop editing” line. The constant wins over the stored value and locks the field on the settings page:

define( 'JPKCOM_HARDEN_TRIM_EMOJI', true );
define( 'JPKCOM_HARDEN_TRIM_HEARTBEAT', 'optimized' );
define( 'JPKCOM_HARDEN_TRIM_POST_REVISIONS', 20 );
define( 'JPKCOM_HARDEN_TRIM_EXEMPT_ROLES', 'editor,author' );

Booleans take true/false, enums an exact value from the table, integers a value from the allowed list, role lists an array or a comma separated string. An invalid value is ignored and the settings page names the constant.

WP_POST_REVISIONS, AUTOSAVE_INTERVAL, DISALLOW_FILE_EDIT and WP_AI_SUPPORT in wp-config.php win over this plugin, including its constants: WordPress follows them, the matching field is locked and its disabled control shows their value the way WordPress reads it (WP_POST_REVISIONS true or -1 as “WordPress default”, a number outside the list as an extra entry), and a JPKCOM_HARDEN_TRIM_* constant for the same setting is marked as ignored.

Something broke. How do I switch everything off?

Add define( 'JPKCOM_HARDEN_TRIM_DISABLE_ALL', true ); to wp-config.php. No feature runs while it is defined. Deactivating the plugin does the same.

Does it work with block themes?

Yes. Block library CSS and global styles are unavailable with block themes (the switches are disabled and do nothing there), because a block theme depends on those styles.

Does it overlap with Rank Math, caching plugins or Defender?

Possibly. SEO plugins may remove the same <head> links or replace the core sitemaps (then the sitemap switch has nothing to do). Caching and optimisation plugins may offer emoji, embed or heartbeat switches. Security plugins may send the same headers; this plugin skips a header another plugin already set in PHP, but cannot see headers from the web server or a CDN. Run each switch in one place only.

What about XML-RPC, comments and the login URL?

Those are covered by sibling plugins: JPKCom Disable XML-RPC, JPKCom Disable Comments and JPKCom Hide Login. This plugin does not duplicate them.

Does it make my site GDPR compliant?

No. See the note in the description.

What happens when I uninstall it?

Deleting the plugin removes its settings option and its cached data (on multisite, from every site). Deactivating keeps them.
